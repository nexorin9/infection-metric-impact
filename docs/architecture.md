# 架构说明

面向接手维护的人。产品的面向用户说明在 `README.md`，本文件只讲内部结构、状态机与审计链。

## 模块分层

| 包 | 职责 | 对外承诺 |
|----|------|----------|
| `app` | 入口与四条通道（窗口 / headless / doctor / 离线演示） | 不含业务逻辑，只做分发 |
| `metriclib` | 口径条目模型、版本并存、状态机、文件型落盘、审计表 | 口径库是唯一权威定义载体 |
| `graph` | 依赖图与影响面展开 | 依赖按口径内容哈希匹配，不按名称 |
| `expr` | 条件树、递归下降解析器、求值器、字段字典对账 | 解析错误带行列位置与错误码 |
| `recompute` | 口径指纹、三桶差异、双版本对拍、差异说明三段、运行摘要 | 同一输入两次结果逐字一致 |
| `connect` | 出站 HTTP 客户端、Bearer 注入、幂等键、退避重试、各端点 | 真实协议；凭据只从环境变量读 |
| `gateway` | 单一 OpenAI 兼容模型网关、三类任务契约、调用审计、降级 | 模型输出永远是草稿 |
| `pkg` | 上级口径包解析、三清单分类、逐条确认、合并与回滚 | 重复导入不重复合并 |
| `ui` | Swing 三栏窗口、设计 token、托盘常驻、三态打磨 | 桌面岗位不碰终端 |
| `common` | 环境变量配置面、内容哈希、原子写、可读错误语义 | 跨模块公共件 |

## 口径条目状态机

```
        ┌──────────────┐  提交复核   ┌──────────────────┐
        │    DRAFT     │ ───────────▶ │  PENDING_REVIEW  │
        │   （草稿）    │              │   （待复核）       │
        └──────┬───────┘              └────┬────────┬────┘
               │ 驳回                     批准 │        │ 驳回
               │ (REJECTED → DRAFT)         ▼        ▼
               │                     ┌──────────┐ ┌───────────┐
               │                     │ PUBLISHED│ │ REJECTED  │
               │                     │ （已发布）│ │  （已驳回）│
               │                     └────┬─────┘ └─────┬─────┘
               │                          │ 停用         │ 退回草稿
               │                          ▼              └──▶ DRAFT
               │                     ┌──────────┐
               └────────────────────▶│ RETIRED  │
                                     │ （已停用）│
                                     └──────────┘
```

- 每次跃迁都校验前置状态；**跳过复核的 `DRAFT → PUBLISHED` 一律被拒绝**，且状态不变。
- 已发布版本的**内容不可直接改**，要改必须新建版本号；草稿改动不影响同指标已发布版本的任何字段。
- 状态推进只能由人工动作触发（模型与脚本只能产出草稿）。

## 审计链

口径的每一次变更都落一条只追加的审计记录：`audit_id`、`indicator_code`、`definition_version`、`actor`、`action`、`timestamp`、`field_diff[{field, before, after}]`、`approver`、`approval_note`。

- **只追加**：不提供改写与删除接口。
- **字段级差异**：只记录真正变化的字段，未变化字段不落审计。
- **可反查**：按 `indicator_code` 可列出从首版到当前版本的完整变更链，按 `definition_version` 可过滤。
- **发布回执**：真实出站发布成功后落一条回执（时间戳 + 变更条目 + 是否真有变更 + 端点返回标识），按指标编码可反查。

## 依赖图与影响面

- **节点** = 口径条目（指标编码 + 口径版本）；**边** = 口径依赖。
- **建图期校验**四类构建错误：自环、短环、长环、悬空边（引用不存在的口径）→ 拒绝建图并列出成环的指标链。
- **查询期错误**两类：未建图即查询 → 拒绝并报非法状态；查询未知 ID → 拒绝并报未找到。
- **边匹配按口径指纹**（口径内容规范化后的 sha256），不按名称——两个只差一词的分母是两个不同口径，绝不连错边。
- **展开默认不跨层**：默认只返回直接依赖；跨层必须显式请求深度，结果逐条标注深度；超出展开预算（默认 500 节点 / 5 层）显式报错而不是静默截断。
- **每条边带依据**：复用了哪个分母、谁什么时候建的；缺依据的边不允许写入。

## 双版本差异

两版口径的差异按固定次序计算：**先解析 → 再统一口径形态 → 再做集合差 → 输出三桶**。

- 三桶 = 分子新增 / 排除新增 / 移除。
- 统一口径形态包含：字段顺序无关、集合去重并排序、`in` / `not_in` 元素顺序无关、`between` 上下界定序。
- **次序可证**：把「先统一再比」与「不统一直接比」放在一起跑，两者在同一组样例上必须给出不同结果——这是有对照测试守着的，不是口头承诺。
- 差异的业务归因分两路：规则通道（按差异条件所在树位置映射到业务维度，不依赖模型，独立可跑）与模型通道（只给候选，标注待人工确认）。规则结论优先。

## 对接层约定

- URL 拼装 = `base_url` + `path` + 查询参数；`Authorization: Bearer $TOKEN` 注入，**令牌只从环境变量读，禁止硬编码、禁止写日志**。
- 幂等键：发布 `sha256(指标编码 | 口径版本)`；合并 `sha256(包版本 | 目标口径版本)`。
- 重试：指数退避，**上限 3 次，仅对 5xx / 超时 / 连接失败重试，4xx 不重试**。
- 错误四分类：连接失败 / 超时 / 4xx / 5xx，各带独立错误码与可读原因，不吞异常。
- 每次外发记录端点、方法、状态码、耗时、重试次数与错误码；日志不含令牌明文。

## 模型网关边界

- 业务层只依赖**一个** `ModelGateway`，不直接耦合厂商 SDK；换服务方只需换 `LLM_BASE_URL`。
- 请求体固定为 `{task, schema_version, payload}`；响应必须是 JSON 且通过本地结构校验，**不合格即失败，不猜测修复**。
- 三个任务契约：口径散文 → 条件树、同指标多措辞归并、两版差异业务归因。
- 错误码五类：连接失败 / 超时 / 响应非 JSON / 结构校验失败 / 空结果；每类都写入调用审计。
- 结构校验失败**不重试**（同输入必然同结果）。
- 降级：模型不可达 → 退回人工录入条件树 + 规则校验，界面标注「口径来源 = 人工」，**发布状态不自动推进**。

## 失败语义

统一的可读失败文案形如「口径 {编码} 声明依赖字段 {字段}，数据源 {来源} 未提供该字段」，同一原因同时出现在界面、运行摘要与差异说明里。

失败不静默改数据：取数失败或字段缺失时，该指标本次复算**显式失败**，不按 0 计入分母，失败原因写进运行摘要。
